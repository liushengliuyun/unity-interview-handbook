# 前言：这本手册怎么用

本手册基于 SVS 项目（Unity 3D 手游，C# + XLua + FairyGUI + HybridCLR + YooAssets）中**实际做过的模块**整理，每一章对应一个可以独立展开讲 15~30 分钟的模块，结构统一为：

- **模块背景**：一句话让面试官知道你负责什么、规模多大。
- **高频问题与回答要点**：面试官最可能问的问题，以及回答时应覆盖的关键词。
- **深水区追问**：进阶面试官会追的第二层、第三层问题，以及深度回答思路。
- **优化方向**：被问"你觉得还能怎么改进"时的储备弹药。

## 使用原则

1. **先讲结论，再讲细节**。任何问题的第一句回答给出定性结论（"这个问题本质是 X"），细节按追问逐层展开，不要一次性倾倒。
2. **所有回答必须落在你真实做过的事上**。手册中的案例都来自真实提交，引用时给出 commit 号可以增强可信度（面试时口头说"我记得当时的提交是……"即可）。
3. **不会的题回到方法论文上**。没做过的方向，用"我们项目当时的做法是……如果换成 X 方案，我会考虑……"的方式借力打力。

# 高频通用问题的"项目化"回答策略

面试通用题（自我介绍、离职原因、亮点项目）通用模板之外，SVS 项目的差异化亮点排序：

1. **内存泄漏审计**（技术深度最强，可讲 Material getter 克隆机制、static 累积、YooAsset 引用计数）
2. **BI 打点 + Adjust 归因**（业务闭环最完整，从协议字段到 token 管理到真机验证）
3. **死代码扫描**（方法论最独特，动态语言死代码判定是普适难题）
4. **FPS 引导系统**（链路最复杂，状态机+时序+表现层联动）
5. **渠道账号隔离**（坑最多，读写侧一致性、盲区补全后 revert 的工程判断）
