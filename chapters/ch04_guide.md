# 第 4 章 引导系统（Guide System）

## 模块背景（开场一句话）

> FPS 玩法的引导系统横跨 Lua 业务层与 C# 战斗层，是"状态机 + 时序 + 表现联动"的复杂链路。我做过：重登悬空引用崩溃修复、双图并跑刷怪超量修复、武器锁三层机制梳理、教学打点口径问题定位，并沉淀了引导调试 skill（debug-guide）。

## 高频问题与回答要点

### Q1: 介绍一下你们的引导系统设计

- **配置驱动**：引导步骤配置在表，可配先后与分支（引导 ID 段 900001-90008、800002 等）。
- **触发链**：`CheckTriggerGuide → IsTriggerStop → IsTriggerComplete → Run → setSkipIndex → Finish`。改引导前必须走读完整链路，不凭局部合理就动手（项目明文规则）。
- **分层**：业务引导（UI 层）与 FPS 引导（战斗层）分开。FPS 引导节点可配运镜/开火锁/视频播放等表现节点。
- **FPS 关卡图**：MissionGraph 资产驱动波次与运镜节点（GuideLevel99_x 系列）。
- **重登恢复是硬指标**：断线重连后引导进度保持。

### Q2: 讲一个你修过的引导 bug（故事 1：重登悬空引用崩溃）

**STAR：**

- **S**：线上崩溃——重登时序下视频对象已被销毁仍调 `CloseVideoObject`，NRE。
- **根因链三层叠加**：
  1. Lua VM 跨 Restart 存活，首登创建的视频对象缓存不失效；
  2. CloseAllUI 关闭 UI 时跳过 UIGuide（不在常规关闭列表）；
  3. videos 缓存表持有已销毁引擎对象 → CloseVideoObject NRE。
- **A**：CloseVideoObject 补 null 守卫（d8743d47）。
- **R**：泛化为测试维度：任何 UI 持有引擎对象缓存的模块都要过"重登后缓存是否失效"检查。**"进度恢复了但对象缓存没重建"是重登类 bug 的通用根因模式**。

### Q3: 讲一个复杂 bug（故事 2：GuideLevel99_5 双图并跑）

**STAR：**

- **S**：99_5 关卡刷怪数量是配置值的两倍，且只有它有问题。
- **T**：回答"为什么只有它"。
- **A**：单差异点排查法——逐项对比 99_5 与其他关卡的配置差异，发现只有 99_5 配了 `earlyInitTime=100`；提前初始化与正常初始化在 InitAsync 重入，MissionGraph 被加载两次，波次系统驱动两遍 → 刷怪×2。
- **修复**：InitAsync 同名图已完成幂等跳过 + EarlyInit 延迟回调守卫（326e7d50be）。
- **R**：泛化句——任何"提前初始化"钩子都要考虑与正常初始化的重入竞争。**"为什么只有它"→ 差异点穷举**是通用 debug 手法。

### Q4: FPS 引导的武器锁机制（背熟）

- **三层锁**：角色锁（视野/移动）— 武器锁（weapon）— 开火锁（fire），恢复必须逐层对应，不能越权恢复。
- **反直觉 API**：无参 `FpsEventLockCharacter` 事件 = "全解锁（含 weapon）"，不是"上锁"。
- **99_2 案例**：运镜收尾节点越权全解锁含武器 → 收尾改只恢复视野/移动（1221de8），开火引导节点首位补全解锁（c19ab54）。两个节点都在 MissionGraph YAML 资产里改——折行拆断带空格 indexOf、反向括号行走、$id 是节点最后键（向后找 _actions 会插错节点）、改完回读校验、ab 需重打包。
- **泛化句**：恢复动作必须与锁定动作逐层对应，不能越权恢复。

### Q5: 引导配置错了怎么定位？（打点 39 案例）

- 教学完成打点（打点 39）一直发不出 → 打点触发依赖 `IsTriggerComplete`，配置 Config431 指向不存在的引导 ID 201104 → 判定恒 false。
- **结论句**："下游 token 配对了也没用，配置是源头"。跨端口径问题不越权修，挂起等口径方（策划/服务端）确认。

## 深水区追问

### 追问 1: 重登恢复怎么做？

- 进度持久化在服务器侧（跨设备），客户端会话内使用。冷启动从存档读、relogin 从 VM 存续状态读，**双路径必须等价**。
- 洞见：进度恢复 ≠ 对象重建，两条恢复路径等价性是设计要点。

### 追问 2: 引导节点为什么用 MissionGraph 资产而不是 Lua 写死？

- 收益在策划侧：波次/运镜/显隐策划可配。
- 代价转移给程序：YAML 手工编辑坑多。**"配置驱动的代价转移给了程序"**——所以才有后文的编辑器工具优化方向。

### 追问 3: 引导调试怎么提效？

- 沉淀 debug-guide skill：链路走读、配置核对、触发链验证，调试流程标准化。

## 优化方向（本模块）

1. MissionGraph 可视化编辑器（消除手工 YAML 编辑）。
2. 编辑器内引导状态 inspection 工具（当前步骤/锁状态/进度实时显示）。
3. 开发期引导快进/跳步/回放。
4. 引导 ID 引用完整性校验进导表管线（杜绝 Config431→不存在 ID 问题）。

## 本章核心记忆点

- 触发链六步 + 双路径等价性 + 三层锁。
- 两个 STAR：重登悬空引用（根因链三层叠加）、99_5 双图并跑（单差异点排查法）。
- 亮点句："进度恢复但对象缓存没重建"是重登类 bug 的通用根因模式；"配置驱动的代价转移给了程序"。
